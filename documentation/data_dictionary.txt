H&M CUSTOMER & OMNICHANNEL ANALYTICS
DATASET / COLUMN DOCUMENTATION

PROJECT SCOPE
-------------
Source: H&M Personalized Fashion Recommendations dataset
Original dataset: https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data

Primary analysis period used in this project:
2019-09-23 through 2020-09-22

Important notes:
- A row in the transaction data represents one purchased article line item, NOT an order.
- The dataset does not contain an order_id.
- The price field is a normalized/transformed value and should not be described as literal currency.
- sales_channel_id is kept as Channel 1 / Channel 2 because the dataset does not officially define the channel labels.
- This file documents only columns that exist in the ORIGINAL H&M dataset.
- Calculated columns and Power BI-only fields are documented in the README instead.


1. transactions_train.csv
-------------------------
Purpose:
Original H&M transaction-level dataset containing customer purchases.

Columns used in this project:

t_dat
- Transaction date.
- Used to define the 12-month analysis period and support monthly trend, purchase-frequency, and recency analysis.

customer_id
- Unique customer identifier.
- Used to connect transaction activity to customer attributes.
- Used for distinct purchasing-customer counts, retention analysis, and customer segmentation.

article_id
- Unique article/product identifier.
- Used to connect transactions to article attributes.
- Used for product-level analysis and distinct purchased-article counts.

price
- Normalized/transformed transaction value.
- Used for customer-value calculations and value-segment analysis.
- Not interpreted as literal currency.

sales_channel_id
- Numeric sales-channel identifier.
- Values in the dataset are 1 and 2.
- Used to analyze Channel 1, Channel 2, and omnichannel purchasing behavior.


2. customers.csv
----------------
Purpose:
Original H&M customer dataset containing customer attributes.

Columns used in this project:

customer_id
- Unique customer identifier.
- Used to connect customer attributes to transaction activity.

age
- Customer age.
- Used for age-group analysis.

club_member_status
- H&M club membership status.
- Examples include ACTIVE, PRE-CREATE, and LEFT CLUB.
- Used to compare customer behavior across membership statuses.

fashion_news_frequency
- Customer fashion-news preference/frequency.
- Examples include NONE, Monthly, and Regularly.
- Used to compare customer behavior by fashion-news subscription preference.


3. articles.csv
---------------
Purpose:
Original H&M article/product dataset containing product attributes.

Columns used in this project:

article_id
- Unique article identifier.
- Used to connect article attributes to transaction activity.

product_group_name
- High-level product grouping.
- Used for product-volume, customer-reach, and product-mix analysis.
- Examples include:
  Garment Upper body
  Garment Lower body
  Garment Full body
  Underwear
  Accessories
  Swimwear
  Socks & Tights
  Shoes
  Nightwear
  Bags
  Items
  Furniture
  Cosmetic
  Garment and Shoe care
  Underwear/nightwear
  Stationery
  Interior textile
  Fun
  Unknown

------------------------
The project also creates cleaned, filtered, and modeled tables such as:

- transactions_12mo
- customers_clean
- articles_clean

- Power BI Date table

These are NOT original H&M dataset tables.

Their creation, calculated fields, segmentation logic, and Power BI modeling details are documented in the project README and SQL scripts rather than in this source-column dictionary.
